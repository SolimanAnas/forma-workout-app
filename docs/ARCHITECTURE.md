## 2. Layered Architecture

Dependencies point **downward only**; a layer never imports from the layer above it.

```text
UI            src/ui/       screens · components · styles
   ↓
Services      src/services/ WorkoutService · ProgressService · AchievementService · VoiceCoach
   ↓
Domain        src/domain/   exercise · rep · workout · progression · signal   (PURE — no browser APIs)
   ↓
Sensors       src/sensors/  SensorManager + browser/native adapters + replay
   ↓
Platform      src/platform/ capability/env detection, permission helpers
```

Supporting: `src/data/` (IndexedDB schema, migrations, repositories) is used by Services; `src/app/`
holds bootstrap + router + shell.

## 3. Enforced Invariants

1. **Pure domain** — nothing in `src/domain/` may import a DOM/`window`/browser global or anything from
   `src/sensors|ui|services|data`. Enforced by ESLint (`no-restricted-imports`) + domain unit tests
   that compile without a DOM.
2. **Sensor flow** — always `Exercise → SensorManager → Adapter`. No exercise code touches
   `DeviceMotionEvent`/Generic Sensor API directly.
3. **Honest capabilities** — every sensor/metric is labeled **Detected / Estimated / Unavailable /
   Unsupported** (spec §8). Never fabricate a reading.
4. **Local-first** — no mandatory account/cloud; user data and app cache are stored and cleared
   separately (spec §17/§18).
5. **No monolith** — no catch-all `app.js`; keep modules small and single-purpose.

## 4. Data Flow (runtime, in a workout)

```text
Adapter samples → SensorManager (normalize, tag source) → domain/signal (filter)
   → domain/rep (state machine) → domain/exercise (profile) → Services → UI (throttled)
                                                             ↘ data/ (persist)
```

UI updates are throttled; the app never re-renders wholesale on each sensor event (spec §21).

## 5. Build & Deploy

- `npm run dev` — Vite dev server.
- `npm run build` — static output to `dist/` (PWA precache generated by `vite-plugin-pwa`).
- `npm run typecheck` / `npm test` / `npm run e2e`.
- Deploy: publish `dist/` to GitHub Pages; `vite.config.ts` `base` must match the repo subpath.
